The Problem

Evidence disagrees.
Silence is not resolution.

Aviation accident investigations draw on a dozen source types — NTSB final reports, FAA accident data, maintenance records, CVR/FDR readouts, ASAP submissions, witness depositions, and news coverage. Every source has a different level of authority. Every source can contain errors.

When sources conflict, the default response is to pick one silently. That choice is invisible to anyone reviewing the record later — including a jury.

Atlas makes every disagreement explicit, every resolution auditable, and every projected fact traceable to its source basis.

Platform Capabilities

Claims. Conflicts. Provenance. Reports.

Every capability is built around a single principle: every projected fact must be traceable to its evidence chain.

⬡

Claims Model

Every field value is a claim from a specific source. Claims have types (RAW, CONFIRMED, MANUAL_OVERRIDE), reliability tiers, ingestion timestamps, and full history.

⚡

Conflict Detection

When active claims for a field disagree, a conflict is raised automatically. Conflicts are first-class states — not bugs, not silenced disagreements.

✓

Auditable Resolution

Reviewers select a winning claim or enter a manual override — both require a written rationale. Every resolution is preserved with curator identity and timestamp.

🔗

Provenance Chain

From any projected fact, navigate the full evidence chain: source → ingestion → claim → conflict → resolution → projection. Audit hashes verifiable independently.

⏱

Timeline Reconstruction

Source-backed event sequences with conflict indicators for uncertain or disputed entries. Every timeline item links to its evidence basis.

📄

Report Export

Generate immutable, versioned PDF reports. Every output fact carries an explicit footnote: source, ingestion timestamp, reliability tier. Mandatory disclaimer on every export.

How It Works

Ingest → Reconcile → Resolve → Export

A deterministic, auditable pipeline from raw sources to a court-submissible record.

01

Ingest sources

Upload PDFs, dockets, and structured records. Text is extracted conservatively. Ingestion is idempotent — re-runs are safe.

02

Detect conflicts

When two active claims for the same field disagree, a conflict is raised. The projected field shows DISPUTED until resolved.

03

Resolve with rationale

Reviewers pick the winning claim or enter a manual override — both require a written rationale. 409 optimistic locking prevents concurrent edits from silently clobbering each other.

04

Export the record

Generate an immutable, versioned report. Every fact footnoted. Resolution history appended. Audit hashes included for independent verification.

Security & Compliance

Designed for legal defensibility from the ground up.

Every architectural decision considers what happens when the record is questioned — in deposition, in court, or in a regulatory proceeding.

Tenant isolation

PostgreSQL row-level security enforces tenant boundaries at the database layer. Tenant-private data cannot leak through public search, maps, or reports.

Audit hash chains

Every claim history entry and conflict resolution carries a cryptographic hash. The chain is independently verifiable without access to the Atlas system.

No API keys in the browser

A Browser-for-Frontend (BFF) proxy holds API keys server-side. The browser holds only an HttpOnly session cookie. X-API-Key never appears in browser network requests.

Append-only evidence store

Claims and conflicts are never deleted or silently edited. Superseded claims remain auditable. The full history of every field value is preserved.

Role-based access control

Analyst (read-only), Reviewer (resolve/ingest/report), Admin. Roles enforced server-side; UI affordances reflect but do not substitute for backend enforcement.

Immutable report exports

Generated reports are versioned, content-hashed, and never overwritten. A report is a snapshot of what was believed at a specific point in time.
